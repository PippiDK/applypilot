# ApplyPilot v0.4 Workflow Merge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restore Search Profile, Application Pack, CV Update Review, and Truth Guard from v0.4 on top of v1.0.3 without changing LinkedIn search/scoring behavior or feeding uploaded CV/profile data into search.

**Architecture:** v1.0.3 remains the project base and the live LinkedIn result schema stays authoritative. New profile/review helpers are isolated in a small client-safe library, UI state is added to `app/page.js`, and v0.4 visual components are merged into the existing live-search master/detail screen. The current parser and search APIs remain untouched.

**Tech Stack:** Next.js 14.2.15, React 18.3.1, Node test runner, localStorage, current `/api/parse-cv` and `/api/linkedin-search` routes.

**Spec:** `docs/superpowers/specs/2026-08-21-v04-v103-merge-design.md`

## Global Constraints

- `app/lib/linkedin-search.js` must remain SHA-256 `5b5527cb5a80c42973384c599ed22ccae241a941e3cea9ada557ff430b84c3e2`.
- `app/api/linkedin-search/route.js` must remain SHA-256 `8f47a242c39747f44237f7e8428f6e0e965cf6c2e5d008a64b306147c94fdd39`.
- The exact `search()` function body in `app/page.js` must remain SHA-256 `f13006d7ca40537c080cc910aaa8105271b541d3d30d371938ad42950205c46e`.
- Uploaded CV/Profile data must not be included in the `/api/linkedin-search` request body and must not alter scoring, filtering, ranking, or result count.
- Keep the current v1.0.3 `/api/parse-cv` implementation unchanged.
- Do not reactivate `/api/tailor-cv` and do not add AI-generated resume content.
- Cover letter remains `Not generated yet`.
- This artifact workspace is not a Git checkout, so steps end with verification snapshots instead of Git commits.

- [ ] **Step 4: Implement minimal helper module**

Use the v0.4 helper semantics exactly for `cleanSource`, `isCompleteEvidence`, and conservative rewrites:

```js
export const DEFAULT_PROFILE={
  cvName:'',
  roles:'Senior Project Manager, Delivery Manager, Technical Project Manager, Program Manager',
  geography:['Denmark hybrid','Remote EU/EMEA'],
  salary:'75000',
  exclusions:'Construction; industrial hardware / manufacturing R&D; coordinator or assistant roles; mandatory Danish',
  savedAt:'',
  factBank:[],
  skills:[],
  cvParsedAt:''
}

export function mergeProfile(saved={}){
  return {...DEFAULT_PROFILE,...saved,geography:Array.isArray(saved.geography)?saved.geography:DEFAULT_PROFILE.geography,factBank:Array.isArray(saved.factBank)?saved.factBank:[],skills:Array.isArray(saved.skills)?saved.skills:[]}
}

export function resumeToProfile(profile,cvData){
  const base=mergeProfile(profile)
  if(!cvData) return base
  return {...base,cvName:cvData.fileName||'',factBank:Array.isArray(cvData.facts)?cvData.facts:[],skills:Array.isArray(cvData.skills)?cvData.skills:[],cvParsedAt:cvData.parsedAt||''}
}
```

Define a fixed review-only vocabulary covering the v0.4/job-delivery concepts: `delivery`, `software`, `platform`, `project`, `program`, `programme`, `implementation`, `integration`, `transformation`, `fintech`, `banking`, `regulatory`, `compliance`, `risk`, `governance`, `stakeholder`, `release`, `cutover`, `uat`, `agile`, `azure`, `data`, `engineering`, `migration`, `cloud`.

Port the v0.4 conservative rewrite rules only:

```js
.replace(/\bLed the delivery of\b/i,'Led delivery of')
.replace(/\bworked closely with\b/ig,'collaborated with')
.replace(/\bhelping to maintain\b/ig,'supporting')
.replace(/\bhelping maintain\b/ig,'supporting')
.replace(/\bin order to\b/ig,'to')
```

Do not insert any job term that was absent from the original fact.
