# ApplyPilot v0.4 → v1.0.3 Merge Design

## Goal

Restore the complete user-facing v0.4 workflow on top of v1.0.3 while preserving the current LinkedIn search and scoring behavior exactly.

The merged version keeps v1.0.3 as the base. v0.4 is used only as the source for Search Profile, Application Pack, CV Update Review, and Truth Guard behavior/UI.

## Non-negotiable invariants

The following v1.0.3 search files and behavior are frozen:

- `app/lib/linkedin-search.js`
- `app/api/linkedin-search/route.js`
- the `search()` function in `app/page.js`
- LinkedIn discovery queries
- full-JD retrieval
- hard exclusions
- scoring weights and thresholds
- ranking and result count
- freshness window behavior
- search statistics and coverage reporting

Uploaded CV/Profile data must not be passed into `/api/linkedin-search` and must not affect evaluation or ranking in this merge.

## Base version

Use v1.0.3 as the full project base. Do not copy v0.4 wholesale.

Keep current v1.0.3 APIs, package setup, tests, LinkedIn engine, current live-result schema, and current resume parser.

## Restored v0.4 functionality

### 1. Search Profile wizard

Restore the six-step profile modal:

1. Upload Master CV
2. Target roles
3. Geography/work model
4. Salary floor
5. Exclusions
6. Confirm profile

Persist profile in `localStorage` under `applypilot-profile`.

Profile is informational/user-controlled state only in this merge. It does not feed the search engine yet.

### 2. Shared Master CV state

Retain the working v1.0.3 PDF/DOCX parser and `/api/parse-cv` route.

Resume upload remains available from the current standalone Master CV button and from Search Profile step 1.

Both upload entry points must use the same parsed data shape:

- file name
- fact bank
- skills/signals
- parsed timestamp

Persist current resume data under `applypilot-master-cv` and mirror it into the Search Profile draft/profile when appropriate. Do not alter parsing logic.

### 3. Application Pack panel

For the selected real LinkedIn vacancy, restore:

- Tailored CV status
- Cover letter status (`Not generated yet`)
- `Review CV changes` action when verified CV facts exist
- fallback to CV/Profile upload when no verified facts exist

Keep the existing live LinkedIn vacancy links and current score breakdown.

### 4. CV Update Review

Restore the v0.4 review modal for the currently selected real LinkedIn vacancy:

- proposed wording changes
- Original → Updated comparison
- Why changed
- Source statement
- Keep original
- Accept change
- Accept all safe changes
- reviewed count

The review operates only on parsed Fact Bank evidence. It must not change the search result, search score, or ranking.

### 5. Truth Guard

Restore v0.4 Truth Guard semantics: proposed changes may only restate text already present in verified CV facts.

Use the v0.4 conservative rewrite behavior. Do not call retired `/api/tailor-cv`, do not add unsupported claims, and do not introduce AI generation in this merge.

Because v1.0.3 jobs no longer contain v0.4 demo `keywords`, derive review-only alignment terms from the current selected job title/JD using a small fixed vocabulary. This derived data is presentation/tailoring-only and is not passed to the search engine.

## UI integration

Keep the current v1.0.3 live-search controls and live-result master/detail layout.

Add the restored v0.4 controls without removing current functionality:

- Search Profile button in the header alongside the LinkedIn source badge
- profile summary strip integrated with the existing Master CV entry point
- Application Pack section in the selected-job detail panel
- CV Update Review summary below the live results
- v0.4 profile/review modals

Do not replace real LinkedIn results with v0.4 demo jobs.

## Data mapping

Current search result shape remains authoritative:

- `item.job.title` → role
- `item.job.company` → company
- `item.job.location` → location
- `item.job.originalUrl` → Open job
- `item.evaluation.score` → displayed score
- `item.evaluation.match` → Why this fits
- `item.evaluation.gaps` → Gap / unknown

CV review receives the selected `item` separately and uses the job title/JD only for relevance/alignment of existing facts.

## Error handling

- Resume parser errors continue using existing v1.0.3 error messages.
- Profile localStorage corruption is ignored safely and falls back to defaults.
- CV review is unavailable when no usable Fact Bank evidence exists.
- Search errors and LinkedIn partial-coverage warnings remain unchanged.

## Tests and verification

Before merge, capture hashes/text of the frozen search engine and `search()` function.

Add tests for:

1. Search Profile persistence and required state contract.
2. CV review proposal functions never introduce content except the allowed conservative v0.4 rewrites.
3. Review terms are derived from the selected LinkedIn JD without mutating the search item.
4. Application Pack becomes reviewable only when Fact Bank evidence exists.

After merge:

- run all existing LinkedIn search tests;
- run resume upload/parser contract tests;
- run new profile/CV-review tests;
- run `npm run build` if dependencies are available;
- verify `app/lib/linkedin-search.js` and `app/api/linkedin-search/route.js` hashes are unchanged;
- verify the body of `search()` in `app/page.js` is byte-for-byte unchanged from v1.0.3;
- inspect the final diff and confirm only frontend/profile/review support code and tests changed.

## Explicitly out of scope

- Changing LinkedIn search logic
- Feeding uploaded CV into search/scoring
- Feeding Search Profile into search/scoring
- New job sources
- Cover-letter generation
- AI resume generation
- `/api/tailor-cv` reactivation
- persistence/database work beyond current localStorage
- new-job history/dedup across runs
