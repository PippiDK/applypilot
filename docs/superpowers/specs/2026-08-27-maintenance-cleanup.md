# ApplyPilot Maintenance Cleanup — Design

## Goal

Stabilize the current TEST branch after the 2026-08-26 product work without changing LinkedIn discovery, scoring, ranking, CV semantics, or user-visible product behavior.

## Scope

1. Stop automatic Vercel Git deployments from `feature/cv-library-3-slots` so ordinary development commits do not consume Preview deployments.
2. Remove only proven dead Best CV selection persistence code left behind after the Best CV panel became informational-only.
3. Refresh project documentation so the repository reflects the current ApplyPilot architecture and today's shipped work.
4. Establish a living backlog with NEXT / PLANNED / UX OBSERVATION / TECH DEBT sections.
5. Record deployment workflow guidance: development stays on the feature branch; a dedicated preview branch is updated only when a manually testable milestone is ready.

## Non-goals / safety constraints

- Do not modify `app/lib/linkedin-search.js`.
- Do not modify `app/lib/linkedin-stable-search.js`.
- Do not modify `app/lib/linkedin-role-gate.js`.
- Do not modify `app/api/linkedin-search/route.js`.
- Do not change Search scoring, ranking, filtering, discovery queries, or CV evaluation behavior.
- Do not merge or update `main`.
- Do not delete uncertain legacy Python/root patch directories in this maintenance pass.
- Do not trigger a new Vercel Preview deployment during maintenance.
- Do not implement filtering/sorting, Persistent Job Analysis, or AI CV Adaptation in this pass.

## Deployment workflow

`feature/cv-library-3-slots` is a development branch and must not auto-deploy. Vercel branch configuration therefore disables Git deployments only for this branch. Unspecified branches retain Vercel's default deployment behavior, allowing a future dedicated `preview/applypilot-test` branch to be used as an explicit manual-preview gate.

## Dead-code cleanup rule

Only remove code whose lack of use is directly proven. In this pass that is the old Best CV user-selection persistence API (`readBestCvSelection`, `writeBestCvSelection`, its private key helper and selection prefix). The Best CV analysis cache itself remains intact.

## Verification

Completion requires:

- targeted Best CV cache tests green;
- full `npm test` green;
- `npm run build` green;
- frozen LinkedIn Search core blob SHAs unchanged from the known baseline;
- `main` still at `354c799c8ffe31e599f175ae4770ae4086a73a91`;
- no unexpected Vercel deployment generated by maintenance commits.
